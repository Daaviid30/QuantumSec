# Deploying QuantumSec

This guide shows the simplest supported way to publish QuantumSec for a small audience such as
tutors or reviewers:

```text
Internet -> HTTPS + password -> Nginx
                                |-- /       -> React static files
                                `-- /api/*  -> FastAPI on 127.0.0.1:8000
```

The examples target a Debian or Ubuntu server with a domain name.

> [!IMPORTANT]
> QuantumSec is research and educational software. It is not a certified production security
> product, and keys generated by the laboratory must never protect real or sensitive data.

## What is deployed

The web application currently provides:

- QKD, PQC, and hybrid session demonstrations;
- BB84 simulations and configurable channel pipelines;
- run history and comparison;
- an AES-256-GCM protected-message demonstration.

The frontend and backend must use the same domain because the browser calls relative `/api/...`
paths.

Runs and live data-plane sessions are stored only in backend memory. A restart clears them, and all
visitors share the same temporary history. For this reason the service must run with **one Uvicorn
worker** until shared persistence is implemented.

## Requirements

Before starting, prepare:

- a Debian or Ubuntu server;
- a domain whose DNS record points to that server;
- inbound ports `80` and `443` open;
- Git;
- Python `3.14` managed by [`uv`](https://docs.astral.sh/uv/getting-started/installation/);
- Node.js `22.12+` or `24+` with npm;
- CMake, Ninja, a C/C++ compiler, and OpenSSL development headers.

GitHub stores the source code but does not run the FastAPI backend. GitHub Pages alone is therefore
not sufficient. The repository may remain private; configure a read-only GitHub deploy key on the
server before cloning it.

## 1. Check the project before deploying

Run these checks on a development machine from the repository root:

```bash
uv sync --dev
uv run pytest
uv run ruff check .

cd ui/frontend
npm ci
npm test
npm run typecheck
npm run build
```

Do not continue if a command fails.

## 2. Prepare the server

Install the operating-system packages:

```bash
sudo apt update
sudo apt install -y \
    apache2-utils \
    build-essential \
    certbot \
    cmake \
    curl \
    git \
    libssl-dev \
    nginx \
    ninja-build \
    python3-certbot-nginx \
    rsync
```

Install `uv` system-wide:

```bash
curl -LsSf https://astral.sh/uv/install.sh | \
    sudo env UV_INSTALL_DIR=/usr/local/bin sh
```

Install Node.js `22.12+` or `24+` using the official
[Node.js downloads](https://nodejs.org/en/download) for Linux, then verify the tools:

```bash
uv --version
node --version
npm --version
```

Create a dedicated service user and application directories:

```bash
sudo useradd --system --create-home \
    --home-dir /var/lib/quantumsec \
    --shell /usr/sbin/nologin \
    quantumsec

sudo install -d -o quantumsec -g quantumsec /opt/quantumsec
sudo install -d -o quantumsec -g quantumsec /var/lib/quantumsec/oqs
```

If the user already exists, skip the `useradd` command.

## 3. Install QuantumSec

Clone the repository. Replace the URL if deploying a fork. For a public repository:

```bash
sudo -u quantumsec -H git clone \
    https://github.com/Daaviid30/QuantumSec.git \
    /opt/quantumsec
```

For a private repository, configure a read-only deploy key for the `quantumsec` user and use the SSH
URL instead:

```bash
sudo -u quantumsec -H git clone \
    git@github.com:Daaviid30/QuantumSec.git \
    /opt/quantumsec
```

Install the locked Python dependencies without development packages:

```bash
sudo -u quantumsec -H bash -lc '
    cd /opt/quantumsec &&
    uv python install 3.14 &&
    uv sync --locked --no-dev
'
```

Build and load the native `liboqs` library once, using the same account that will run the service:

```bash
sudo -u quantumsec -H env \
    OQS_INSTALL_PATH=/var/lib/quantumsec/oqs \
    LD_LIBRARY_PATH=/var/lib/quantumsec/oqs/lib \
    /opt/quantumsec/.venv/bin/python -c \
    "import oqs; print('liboqs loaded successfully')"
```

The first import can take several minutes because `liboqs-python` may download and compile
`liboqs`. It must finish during installation, not on the first web request.

## 4. Build the frontend

```bash
sudo -u quantumsec -H bash -lc '
    cd /opt/quantumsec/ui/frontend &&
    npm ci &&
    npm run build
'

sudo install -d -o root -g root /var/www/quantumsec
sudo rsync -a --delete \
    /opt/quantumsec/ui/frontend/dist/ \
    /var/www/quantumsec/
```

> [!CAUTION]
> `rsync --delete` removes destination files that are not present in `dist/`. Use it only with the
> dedicated `/var/www/quantumsec/` directory shown above.

## 5. Create the backend service

Create `/etc/systemd/system/quantumsec.service`:

```ini
[Unit]
Description=QuantumSec FastAPI backend
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=quantumsec
Group=quantumsec
WorkingDirectory=/opt/quantumsec
Environment=PYTHONUNBUFFERED=1
Environment=PYTHONDONTWRITEBYTECODE=1
Environment=OQS_INSTALL_PATH=/var/lib/quantumsec/oqs
Environment=LD_LIBRARY_PATH=/var/lib/quantumsec/oqs/lib
ExecStart=/opt/quantumsec/.venv/bin/uvicorn ui.backend.main:app --host 127.0.0.1 --port 8000 --workers 1 --proxy-headers --forwarded-allow-ips=127.0.0.1
Restart=on-failure
RestartSec=5
NoNewPrivileges=true
PrivateTmp=true
ProtectHome=true
ProtectSystem=strict
MemoryMax=2G
TasksMax=64

[Install]
WantedBy=multi-user.target
```

Start it and verify the local health endpoint:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now quantumsec
sudo systemctl status quantumsec
curl --fail http://127.0.0.1:8000/api/health
```

The response should contain `"status":"ok"`. If the service fails, inspect it with:

```bash
sudo journalctl -u quantumsec -n 100 --no-pager
```

## 6. Configure Nginx and password access

Create a password for the tutor account:

```bash
sudo htpasswd -c /etc/nginx/quantumsec.htpasswd tutor
sudo chown root:www-data /etc/nginx/quantumsec.htpasswd
sudo chmod 640 /etc/nginx/quantumsec.htpasswd
```

Use a unique password and share it privately. Basic authentication must only be used over HTTPS.

Create `/etc/nginx/conf.d/quantumsec-limits.conf`:

```nginx
limit_req_zone $binary_remote_addr zone=quantumsec_api:10m rate=2r/s;
limit_conn_zone $binary_remote_addr zone=quantumsec_connections:10m;
```

Create `/etc/nginx/sites-available/quantumsec` and replace `quantumsec.example.com` with the real
domain:

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name quantumsec.example.com;

    root /var/www/quantumsec;
    index index.html;

    auth_basic "QuantumSec review";
    auth_basic_user_file /etc/nginx/quantumsec.htpasswd;

    client_max_body_size 32k;
    limit_conn quantumsec_connections 5;
    limit_req_status 429;

    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "DENY" always;
    add_header Referrer-Policy "no-referrer" always;

    location /api/ {
        limit_req zone=quantumsec_api burst=4 nodelay;

        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 10s;
        proxy_read_timeout 120s;
        proxy_send_timeout 120s;
    }

    location = /docs {
        proxy_pass http://127.0.0.1:8000/docs;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location = /openapi.json {
        proxy_pass http://127.0.0.1:8000/openapi.json;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

Enable and validate the site:

```bash
sudo ln -s /etc/nginx/sites-available/quantumsec /etc/nginx/sites-enabled/quantumsec
sudo nginx -t
sudo systemctl reload nginx
```

## 7. Enable HTTPS

Request a Let's Encrypt certificate. Replace the domain and email:

```bash
sudo certbot --nginx \
    -d quantumsec.example.com \
    -m your-email@example.com \
    --agree-tos \
    --redirect
```

Test automatic renewal:

```bash
sudo certbot renew --dry-run
```

Only ports `80` and `443` should be reachable from the Internet. Never expose port `8000`.

## 8. Final verification

Open `https://quantumsec.example.com` in a private browser window and check:

1. Nginx asks for the tutor username and password.
2. The interface loads and reports that the backend is connected.
3. A QKD, PQC, or hybrid session can be executed.
4. The new run appears in the history and comparison views.
5. The protected-message demonstration works for a compatible session.
6. `https://quantumsec.example.com/docs` is also password-protected.

You can also check the public route from a terminal:

```bash
curl --fail --user tutor https://quantumsec.example.com/api/health
```

The command asks for the password if it is omitted from the URL and shell history.

## Updating the deployment

Run:

```bash
sudo -u quantumsec -H git -C /opt/quantumsec pull --ff-only

sudo -u quantumsec -H bash -lc '
    cd /opt/quantumsec &&
    uv sync --locked --no-dev &&
    OQS_INSTALL_PATH=/var/lib/quantumsec/oqs \
    LD_LIBRARY_PATH=/var/lib/quantumsec/oqs/lib \
    .venv/bin/python -c "import oqs"
'

sudo -u quantumsec -H bash -lc '
    cd /opt/quantumsec/ui/frontend &&
    npm ci &&
    npm run build
'

sudo rsync -a --delete \
    /opt/quantumsec/ui/frontend/dist/ \
    /var/www/quantumsec/

sudo systemctl restart quantumsec
curl --fail http://127.0.0.1:8000/api/health
```

Re-run the checks from section 1 before deploying an important update.

## Local development

Start the backend from the repository root:

```bash
uv sync --dev
uv run uvicorn ui.backend.main:app --reload --host 127.0.0.1 --port 8000
```

Start the frontend in another terminal:

```bash
cd ui/frontend
npm ci
npm run dev
```

Open `http://localhost:5173`. Vite proxies `/api` to the backend on port `8000`.

## Troubleshooting

### The backend does not start

```bash
sudo systemctl status quantumsec
sudo journalctl -u quantumsec -n 100 --no-pager
```

If the error mentions `oqs`, repeat the `liboqs` import from section 3 as the `quantumsec` user.

### Nginx returns `502 Bad Gateway`

```bash
curl --fail http://127.0.0.1:8000/api/health
sudo nginx -t
```

A failed local health check indicates a backend problem. A successful local check usually indicates
an Nginx configuration problem.

### A run exists but later returns `404`

Confirm that the systemd command still uses `--workers 1` and that only one QuantumSec backend
instance is running. Run history is process-local and is cleared by restarts.

### The browser reports that the backend is unavailable

Confirm that the frontend and `/api` use the same HTTPS domain. A separate frontend domain requires
code changes for the API base URL and explicit CORS configuration and is outside this guide.
